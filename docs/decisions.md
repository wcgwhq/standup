# Decisions

Project-wide. Site decisions are in `../site/docs/decisions.md`.

- 2026-11-16: One repository for everything (Radu: "I want everything in one place"). Plain folders, not git submodules: `plugin/`, `site/`, `docs/`, `archive/`. The site repository became the parent so its history survived; the plugin, which had never been in git, moved in from `~/development/standup`.
- 2026-11-16: The marketplace manifests moved to the repository root and point at `plugin/`, because every agent installs by repository address. Gemini CLI wants its manifest and a `skills/` folder at the root, so `gemini-extension.json` is there and `skills` is a link to `plugin/skills`. Grok installs the subfolder with `#plugin`.
- 2026-11-16: The folder on disk is still called `standup-site`, because it was renamed under a live session. Rename it to `standup` when nothing has it open.
- 2026-11-16: The skills in `~/.claude/skills/` were copied to `archive/`, not moved. They are still what `/eod-review` runs until the plugin is installed and they are removed.
- 2026-11-16: The GitHub home is the organisation `wcgwhq` (Radu's pick; `wcgw`, `whatcouldgowrong` and `what-could-go-wrong` were taken), repository `wcgwhq/standup`, branch `main`. Created private first, although a public repository was approved, because the commit history carries a personal email and going public is the step that cannot be undone. See `publishing.md`.
- 2026-11-16: The publisher is What Could Go Wrong (Radu: "what could go wrong is the publisher. Even if that, for now, means just me"). The four manifests say so. The About page still names Radu as the person who built it.
- 2026-11-16: The whole repository is MIT, with a `LICENSE` at the root so GitHub and the marketplaces can see it. MIT because the plugin is free, has no dependencies to protect, and Cursor's marketplace and Anthropic's directory both need an open licence. The copyright line is "What Could Go Wrong (Radu Ceuca)": the studio is not a registered company, so a person stays named.
- 2026-11-17: The root `README.md` is the front page people land on: hero, install table, a real update, then what it reads. The reference stays in `plugin/README.md`. Its images are in `docs/readme/`, in light and dark pairs shown with `<picture>`, captured from the built homepage with JavaScript off (768px wide, 2x, everything but the subject hidden). There is no script for it yet; recapture them when `site/src/data/sample-report.json` or the homepage art changes.
- 2026-11-17: The plugin is asked in the product's own word. Both skills' descriptions, which are what an agent matches a request against, now lead with "standup update" and name the phrases Radu listed ("write my standup update", "what have we done today", "what have you worked on today"); "EOD" and "EOW" still work. The site, the README and the plugin README say "write my standup update" wherever they said "ask for today's EOD". The skills keep their names (`eod-review`, `eow-review`): renaming them would break installs.
- 2026-11-17: A third skill, `standup`, is the plugin's front door (`plugin/skills/standup/SKILL.md`): it picks `eod-review` or `eow-review` from the request, has no script of its own, and ends with a "Try next" line of three requests the user has not just made. In Claude Code it is `/standup:standup`. Agents that copy skills now copy the whole `plugin/skills/` folder, which also made that command shorter. The two working skills are unchanged.
- 2026-11-17: The plugin is one skill, `standup`, at 0.6.0. `eod-review` and `eow-review` are gone, at Radu's call: there were no installs to protect and two more names to explain. `plugin/skills/standup/` holds `SKILL.md` (the day report and the routing), `week.md` (a week, a month or a range, read only when asked for), the two scripts (`standup.py`, `standup_week.py`), the voices and the example files. The week script imports the day engine from its own folder, so the two can no longer be installed apart. Settings moved from `~/.claude/eod-review/` to `~/.claude/standup/`. The update's own title line still reads "EOD <day>": that is the report's format, set by the user's style file, and was left alone.
- 2026-11-17: The update's title line is "Standup EOD Wednesday, November 11th, 2026", Radu's format: the product's name, then EOD, then the date written out. A week is "Standup EOW November 9th → November 15th, 2026" and a month "Standup November 2026"; those two are an extension of his format, not his words. The rule is in `SKILL.md` and `style.example.md`; the site's sample titles are rewritten to it and its note says so.
